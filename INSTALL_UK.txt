NEXORA COMMERCE 3.70.1 — КОРОТКА ІНСТРУКЦІЯ ВСТАНОВЛЕННЯ

1. Сервер: PHP 8.4 або 8.5, MySQL 8.4+ або MariaDB 10.11+ LTS (рекомендовано MariaDB 11.4 LTS), InnoDB, utf8mb4, HTTPS.
2. PHP extensions: ctype, curl, dom, fileinfo, gd, iconv, intl, json, mbstring, openssl, pcre, PDO, pdo_mysql, session, simplexml, sodium, tokenizer, zip.
3. Завантажте й розпакуйте весь release в один каталог, наприклад /home/account/nexora-commerce/.
4. Document Root домену встановіть на /home/account/nexora-commerce/public/.
5. Відкрийте https://ваш-домен/setup.php.
6. Заповніть дані БД, магазину й адміністратора та виконайте встановлення.
7. Після встановлення відкрийте /admin/login.

ОНОВЛЕННЯ ІСНУЮЧОЇ УСТАНОВКИ (без видалення даних):
1. Зробіть резервну копію БД і файлів.
2. Розпакуйте новий архів ПОВЕРХ поточного каталогу (.env, .env.local, var/, public/media/ зберігаються; архів їх не містить).
3. Відкрийте https://ваш-домен/upgrade.php, введіть APP_SECRET з .env.local і натисніть «Оновити систему».
   Або по SSH: php bin/upgrade.php
   Скрипт видалить застарілі файли попередніх версій, очистить кеш і застосує зміни БД.
4. Якщо після розпакування вже не відкривається сайт — просто виконайте крок 3, він це виправляє.

ПІСЛЯ ВСТАНОВЛЕННЯ НІЧОГО ПЕРЕНОСИТИ НЕ ПОТРІБНО.
Не копіюйте index.php, public, var або config в інші каталоги.

За замовчуванням: Україна, українська uk-UA, гривня UAH, Europe/Kyiv.
Системні URL залишаються англійськими: /cart, /checkout, /shipping, /about-us тощо.

ВАЖЛИВО: якщо setup.php показує "vendor — відсутній", перед вами source-пакет. Для прямого встановлення потрібен production-release з Composer vendor або необхідно попередньо виконати composer install.

Повна інструкція: docs/INSTALLATION.md


ДЕМО:
Під час браузерної установки можна залишити позначку «Встановити презентаційне демо». Через CLI після встановлення: php bin/console commerce:demo:install. Видалення: php bin/console commerce:demo:remove.

CRON / АВТОМАТИЗАЦІЯ:
Після встановлення достатньо одного cron-запису кожні 5 хвилин. Готовий рядок
(з абсолютними шляхами саме вашої інсталяції) показано в адмінці «Система → Cron / Автоматизація»:
*/5 * * * * /usr/bin/php /шлях/до/проєкту/bin/console commerce:cron:run >/dev/null 2>&1
Вказуйте абсолютний шлях до PHP командного рядка (не php-fpm) тієї ж версії, що й сайт.
Немає shell-cron? На тій самій сторінці є секретна веб-адреса /cron/<токен> для планувальника хостингу
та вбудований резервний запуск (працює лише під час відвідувань сайту, тому серверний cron усе одно кращий).
Усі внутрішні задачі, останній сигнал cron і кнопка «Запустити зараз» — на тій самій сторінці.

ЗБІРКА PRODUCTION-RELEASE І ДОСТУП ДО NPM / PACKAGIST:
Залежності потрібні лише на машині збірки. Сам production-сервер після one-upload збірки не потребує Node.js або Composer.

Машина збірки повинна мати вихідний HTTPS (TCP 443) і робочий DNS щонайменше до:
registry.npmjs.org
packagist.org
repo.packagist.org
getcomposer.org
api.github.com та github.com — для пакетів, які Composer отримує з GitHub.

Швидка перевірка мережі:
getent hosts registry.npmjs.org
getent hosts repo.packagist.org
curl -I https://registry.npmjs.org/
curl -I https://repo.packagist.org/
npm ping

Якщо використовується HTTP(S)-proxy, задайте HTTPS_PROXY/HTTP_PROXY для shell, а для npm за потреби npm config set proxy та npm config set https-proxy. Не вимикайте перевірку TLS і не використовуйте strict-ssl=false.

Після появи мережевого доступу з кореня SOURCE-пакета виконайте:
bash tools/bootstrap-production-online.sh

Скрипт створить справжні composer.lock і package-lock.json, встановить vendor, виконає npm ci, typecheck, dependency audit, Vite build, перевірку assets і сформує production ZIP. Якщо будь-який dependency/build крок не пройде, production-архів створюватися не повинен.

ВІДНОВЛЕННЯ ПАРОЛЯ АДМІНІСТРАТОРА
На сторінці входу є посилання «Забули пароль?» (лист із посиланням, чинним 30 хвилин). Якщо пошта ще не налаштована, задайте новий пароль командою:
php bin/console commerce:admin:reset-password admin@example.com
