# Declarative extension settings schema v2

The authoritative JSON meta-schema is `extensions/settings.schema.json`. Runtime accepts schema versions 1 and 2; new extensions generated by the SDK use version 2.

Version 2 field types are `text`, `textarea`, `number`, `integer`, `boolean`, `select`, `url`, `email`, `secret`, `color`, `range`, `multilingual_text` and `multilingual_textarea`.

Common properties are `key`, `type`, `label`, `help`, `required` and `default`. Version 2 also supports `group`, `placeholder` and `advanced`. Numeric/range fields may use `min`, `max` and `step`. Select fields use declarative `options` only.

`secret` values never accept a packaged secret default. Admin renders them as password inputs with a reveal/hide control. Leaving an existing secret blank preserves it. Newly supplied values are encrypted before database storage and are never returned to the form in clear text.

`multilingual_text` and `multilingual_textarea` are stored as locale-keyed values and should be used for merchant-facing copy that differs between active storefront languages.

Each successful settings save stores the previous state as a revision. Rollback first snapshots the current state and then restores the selected revision, so rollback itself is reversible.

Script, callback, handler, raw HTML and PHP-template properties are not accepted in the declarative settings schema. Executable behavior belongs in a signed `trusted_release` or an external `remote_app`.

Nexora 3.5.0 is pre-public-release and accepts only `schema_version: 2`. There is intentionally no Settings Schema v1 compatibility layer.
