# Встановлення Nexora Commerce

Основний сценарій розрахований на те, що після встановлення не потрібно переносити, копіювати або перейменовувати файли системи.

## 1. Вимоги до сервера

Обов'язково:

- PHP 8.4 або 8.5;
- MySQL 8.4+ або MariaDB 11.4+; для нових серверів бажані актуальні LTS-гілки;
- InnoDB;
- utf8mb4;
- HTTPS для робочого магазину;
- PHP extensions: ctype, curl, dom, fileinfo, gd, iconv, intl, json, mbstring, openssl, pcre, PDO, pdo_mysql, session, simplexml, sodium, tokenizer, zip;
- можливість задати кореневий каталог домену на папку `public/`.

Рекомендовано:

- OPcache;
- HTTP/2 або HTTP/3;
- достатній `memory_limit` не менше 256M для звичайного магазину;
- `upload_max_filesize` та `post_max_size` відповідно до максимального розміру медіафайлів;
- Redis лише для великих магазинів або кількох серверів; для запуску він не потрібен.

Не потрібні для звичайного production-сервера, якщо використовується готовий release ZIP:

- Node.js;
- npm;
- Composer.

Вони потрібні лише для збирання release із source-коду.

## 2. Правильне розміщення файлів

Рекомендована структура:

`/home/account/nexora-commerce/`

У цьому каталозі залишаються всі файли системи: `src/`, `config/`, `vendor/`, `var/`, `public/`, migrations та інші файли.

Кореневий каталог домену повинен вказувати тільки на:

`/home/account/nexora-commerce/public/`

Це важливо для безпеки: конфігурація, `.env.local`, вихідний код, migrations та службові файли не повинні бути доступні через браузер.

Після встановлення НЕ потрібно:

- переносити `index.php`;
- копіювати `public/` у іншу папку;
- переносити `var/`;
- переносити `media/`;
- копіювати конфігурацію;
- видаляти install-папку вручну.

Уся система залишається в одному каталозі.

## 3. Встановлення готового production-release

1. Створіть порожню базу MySQL/MariaDB і користувача БД. Інсталятор також може створити базу, якщо користувач має відповідне право.
2. Завантажте ZIP системи на сервер.
3. Розпакуйте ZIP, наприклад у `/home/account/nexora-commerce/`.
4. У панелі хостингу змініть Document Root домену на `/home/account/nexora-commerce/public/`.
5. Відкрийте `https://ваш-домен/setup.php`.
6. Інсталятор українською перевірить PHP, extensions, права каталогів, runtime та готовність release.
7. Введіть параметри БД, назву магазину, ім'я адміністратора, email і пароль.
8. Запустіть встановлення.
9. Після успіху відкрийте `/admin/login`.

Інсталятор перед запуском міграцій додатково перевіряє фактичний Document Root `public/`, реальний запис/перейменування/видалення тимчасового файла, PHP temporary directory, PHP CLI 8.4/8.5 і синтаксис `bin/console`, `utf8mb4` collation, `foreign_key_checks`, а також реальними тестовими DDL/DML операціями права користувача БД на CREATE/ALTER/INDEX/REFERENCES/INSERT/SELECT/UPDATE/DELETE/DROP. HTTPS є обов’язковим для не-localhost production URL. OPcache, вихідний HTTPS, symlink, `upload_max_filesize >= 64M`, `post_max_size >= 64M`, `max_execution_time >= 120` і `max_input_vars >= 3000` перевіряються як production-рекомендації.

Інсталятор автоматично:

- створює `.env.local`;
- генерує випадковий `APP_SECRET`;
- перевіряє MySQL/MariaDB;
- виконує всі migrations;
- створює магазин;
- створює адміністратора;
- встановлює Україну як країну за замовчуванням;
- встановлює українську `uk-UA` як мову за замовчуванням;
- встановлює гривню `UAH` як валюту за замовчуванням;
- встановлює `Europe/Kyiv`;
- створює основний склад;
- створює базові інформаційні сторінки як чернетки;
- блокує повторний запуск installer.

## 4. Якщо використовується source ZIP

Source ZIP не містить Composer `vendor/` і не є готовим one-upload release.

На build-машині або сервері розробки потрібно виконати:

`composer install --no-dev --optimize-autoloader --classmap-authoritative`

Потім для frontend-збірки:

`npm ci`

`npm run typecheck`

`npm run build`

Після цього перевірити:

`php bin/release-check.php`

Для звичайного власника магазину цей сценарій не є цільовим. Фінальний production ZIP повинен уже містити `vendor/` і зібрані assets.

## 5. Що створюється за замовчуванням

- країна: Україна (`UA`);
- основна мова: українська (`uk-UA`);
- валюта: гривня (`UAH`);
- часовий пояс: `Europe/Kyiv`;
- інтерфейс installer: український;
- інтерфейс магазину: український;
- базова адміністративна частина: українська;
- email-шаблони: українські;
- системні URL залишаються стабільними англійськими: `/cart`, `/checkout`, `/account`, `/shipping`, `/payment`, `/about-us`, `/privacy-policy` тощо.

Технічні коди, API-параметри, назви пакетів Composer/npm та URL не перекладаються, оскільки це частина стабільного програмного контракту.

## 6. Після встановлення

Файли переносити не потрібно. Потрібно лише налаштувати магазин:

- заповнити реквізити компанії;
- заповнити й опублікувати інформаційні та юридичні сторінки;
- налаштувати служби доставки;
- налаштувати спосіб оплати;
- налаштувати SMTP;
- за бажанням Telegram;
- підключити Google Merchant/Analytics після введення відповідних облікових даних;
- перевірити System Health.

Redis, зовнішній пошук та окремі workers не потрібні маленькому магазину для старту.

## 7. Оновлення

Оновлення повинно встановлюватися як новий release, а не копіюванням окремих PHP-файлів поверх працюючої версії. Перед переключенням версії система повинна виконати compatibility/preflight, backup/checkpoint, migrations та health checks. Додаткові розширення не мають права змінювати Core-файли.

До завершення production Update Engine не слід вручну замінювати випадкові файли поверх працюючого магазину.

## 8. Презентаційне демо для тестового сервера

Під час першого встановлення installer пропонує прапорець «Встановити презентаційне демо». Для тестового сервера його можна залишити увімкненим.

Після звичайної установки демо можна додати окремо:

`php bin/console commerce:demo:install`

Видалити лише демо-дані:

`php bin/console commerce:demo:remove`

Детальний склад демо: `docs/DEMO_UK.md`.
