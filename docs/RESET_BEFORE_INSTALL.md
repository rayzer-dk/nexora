# Очистка незавершённой установки на сервере

Перед удалением сделайте полный экспорт базы данных и копию файлов сайта. Проверьте, что выбрана отдельная база новой Nexora Commerce, а не действующего магазина.

Ошибка MySQL `#1451 Cannot delete or update a parent row` означает, что таблицу ещё использует внешний ключ. На предоставленном снимке в базе `fermatech` остались две таблицы: `mc_brand` и `mc_media_asset`. Если после резервной копии в разделе «Структура» по-прежнему видны **только эти две таблицы**, выполните в SQL-вкладке phpMyAdmin **одним запросом**:

```sql
SET FOREIGN_KEY_CHECKS = 0;
DROP TABLE IF EXISTS `mc_brand`, `mc_media_asset`;
SET FOREIGN_KEY_CHECKS = 1;
```

Отключение проверки действует лишь для текущего соединения. Не запускайте эти строки по отдельности в разных сессиях. После выполнения обновите список таблиц. Если в базе есть другие таблицы, сначала определите, принадлежат ли они Nexora; приведённый запрос их не удаляет. Не отключайте внешние ключи постоянно.

Для новой установки также проверьте, что в каталоге проекта нет старого `var/install/installed.lock` и старого `.env.local` с настройками предыдущей попытки. Удаляйте их только после резервной копии и только если установка действительно не была завершена. Если магазин уже работал, используйте восстановление из резервной копии вместо повторной установки.

На многих серверах PHP, который обслуживает сайт, и PHP для командной строки могут иметь разные версии. Проверка установщика показала веб-PHP 8.5.10 и `/usr/bin/php` 8.1.34. Установка через браузер запускается внутри веб-PHP, поэтому это предупреждение не блокирует её. Для `bin/console` и cron нужен исполняемый PHP 8.4 или 8.5. Уточните путь к нему у поддержки хостинг-провайдера и укажите этот путь в командах cron; смена версии PHP в настройках сайта сама по себе не доказывает смену `/usr/bin/php`.

Загружайте полный production-архив, содержащий `vendor/autoload_runtime.php` и `public/build/.vite/manifest.json`. Source ZIP не предназначен для установки одним архивом.
