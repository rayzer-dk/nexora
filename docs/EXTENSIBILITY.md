# Наскільки гнучка система: що можна змінити модулем

Модуль Nexora нічого не змінює у файлах системи: він підключається через оголошені точки розширення. Нижче — чесна карта: що вже можна зробити модулем, а що поки потребує зміни самого ядра.

**Типи модулів.** *Декларативний* — без власного PHP-коду (налаштування, переклади, стилі, блоки), підпис не потрібен. *remote_app* — інтеграція із зовнішнім сервісом по HTTPS. *Підписаний* (`trusted_release`) — із власним PHP/JS, встановлюється лише після перевірки підпису вашим ключем (ключ — у `var/config/trusted-publishers.json`).

## Що можна зробити модулем

| Що потрібно | Як | Тип модуля |
| --- | --- | --- |
| Нова сторінка вітрини з текстом | `pages` у манифесті | декларативний |
| Поля налаштувань модуля в адмінці | `settings.schema.json` | декларативний |
| Блок на сторінці товару, категорії, кошика, оформлення, акаунта, у картках адмінки | `slot_contributions`, 36 слотів (`EXTENSION_SLOTS.md`) | декларативний |
| Новий компонент у конструкторах сторінок | `blocks` | декларативний |
| Власні переклади модуля | `translations/` | декларативний |
| Стилі | `assets` (css) | декларативний |
| Нова тема | пакет теми: токени, шаблони, налаштування | декларативний / підписаний (якщо Twig-шаблони) |
| Зв'язок із зовнішнім сервісом (CRM, склад) без PHP | `remote_app`, API і вебхуки | remote_app |
| Власний маршрут, API, обробник | `routes`, `trusted_handler` | підписаний |
| Сторінка модуля в адмінці з правами | `/admin/extensions/<код>/…` + оголошений дозвіл | підписаний |
| Реакція на подію (замовлення, оплата, товар, клієнт…) | `events`, 31 подія (`php bin/console commerce:extension:list-events`) | підписаний |
| Періодична задача (cron) | `scheduled_tasks` | підписаний |
| Власні таблиці й міграції з відкотом | `migrations/` | підписаний |
| Спосіб оплати, спосіб доставки | `provider.payment`, `provider.shipping` | підписаний |
| Блок товару з логікою | `provider.product_block` | підписаний |
| Ще одна мовна модель або сервіс машинного перекладу | `provider.ai`, `provider.translation` | підписаний |
| Джерело курсів валют | `provider.exchange_rate` | підписаний |
| Пошуковий рушій | `provider.search` | підписаний |
| Канал сповіщень (SMS-шлюз, месенджер) замість вбудованого відправника каналу | `provider.notification_sender` | підписаний |
| Формат фіду / маркетплейс | `provider.feed` | підписаний |
| Шаблони документів замовлення | підписана тема: перевизначення Twig-шаблонів документів | підписаний |
| JavaScript на вітрині | `assets` (js) | підписаний |

Модуль можна вимкнути, оновити, відкотити й видалити з адмінки; його дані за замовчуванням зберігаються до явного видалення.

## Що поки не розширюється модулем

Ці місця навмисно не відкриті для коду модуля:

- розрахунок податків і знижок: вони визначають гроші в замовленні, тому змінюються налаштуваннями, а не чужим кодом;
- провайдери captcha: це захист входу й форм, підміна провайдера модулем ослабила б безпеку;
- формати імпорту й експорту: єдиної точки розширення немає (імпорт з OpenCart, CSV й експорт створюються окремими сервісами); потрібна окрема абстракція.

Канал сповіщень, який модуль додає, обслуговує існуючі канали (`email`, `telegram`, `sms`, `in_app`, `web_push`): новий відправник каналу замінює вбудований. Новий тип каналу потребує зміни переліку в ядрі.

Подія, на яку підписаний модуль, повідомляє про факт; чи може обробник **змінити** результат, залежить від події (див. `EVENT_BUS.md`).

## Як перевірити модуль перед встановленням

`php bin/console commerce:extension:validate модуль.zip` і `commerce:extension:test модуль.zip` перевіряють пакет без установки. У адмінці пакет спочатку лише перевіряється й готується; активується окремою кнопкою.
