## Подтверждённые TASK-ID

### TASK-01 — модуль не может добавить cron и обработчик очереди
- Тип: незавершённая функция. Severity: medium. Компонент: `src/Core/Scheduler`, `src/Core/Extension`.
- Состояние: `ScheduledTaskRegistry::all()` — жёстко заданный список ядра. `TrustedExtensionContext` умеет только `route`, `on` и провайдеры.
- Проблема: требование «модуль создаёт cron / queue handler» не выполнено, модулю приходится просить правки ядра.
- Правильное состояние: манифест объявляет `scheduled_tasks`; доверенный модуль регистрирует обработчик; задача видна в Cron админки, отключается вместе с модулем.
- Ответственный: Module Developer. Критерий PASS: E2E — модуль с задачей появляется в Cron, выполняется, исчезает после отключения.

### TASK-02 — слоты расширений не описаны
- Тип: документация. Severity: low. Компонент: `docs/EXTENSION_SDK.md`.
- Состояние: 36 точек (`php bin/console commerce:extension:list-points`) видны только через CLI.
- Правильное состояние: документ со списком слотов и их контекстом, который проверяется тестом на совпадение с кодом.
- Ответственный: Module Developer. Критерий PASS: проверка падает, если слот добавлен без записи в документе.

### TASK-03 — конструкторы категории, блога и корзины (закрыт)
- Категория: сделано. Конструктор «Страница категории» (`/admin/appearance/builder/category`) задаёт порядок сортировки, подборки и товаров, включает и выключает заголовок, фильтры, подборку и нижний текст, видимость по устройствам. Блок товаров выключить нельзя; без публикации действует прежний вид. Тест `category-builder.spec.ts`: публикация меняет страницу, откат возвращает прежний вид.
- Корзина: сделано. Конструктор корзины (`/admin/appearance/builder/cart`): заголовок, «Зберегти кошик» и «Нещодавно переглянуті» — порядок и видимость по устройствам. Товары и подытог с кнопкой оформления остаются всегда. Тест `cart-builder.spec.ts`.
- Блог: NO CHANGE. Страница списка уже настраивается в «Вигляд → Блог» (интро, рубрики, поиск, избранное, теги, RSS, сетка и колонки, тест `blog-display.spec.ts`). Второй конструктор создал бы второй источник правды.

### TASK-04 — новые сервисы без модульных тестов
- Тип: тестовое покрытие. Severity: low. Компоненты: `CampaignTemplateService`, `RuntimeMailer`, `NotificationChannelSettings`, `EmailHtmlAttributeSanitizer`.
- Состояние: покрыты только E2E.
- Ответственный: Module QA. Критерий PASS: тесты на сохранение/удаление шаблона, выбор транспорта и очистку HTML.

### TASK-05 — единый проход по пустым состояниям и ошибкам
- Проверено на 390, 768 и 1440 px: 404 (страница, категория, товар), пустой поиск, пустая корзина, вход. Горизонтальной прокрутки нет, заголовки на месте.
- Найдена и закрыта ошибка (TASK-08). Проверка закреплена тестом `error-and-empty-states.spec.ts`.
- Не охвачено: состояния загрузки и ошибки форм оформления заказа.

### TASK-08 — страница ошибки без CSP nonce (закрыт)
- Тип: ошибка. Severity: medium. Компонент: `SecurityHeadersSubscriber`.
- Состояние: страница 404 строится подзапросом, в котором нет атрибутов основного запроса; шаблоны печатали `nonce=""`, браузер блокировал встроенные скрипты (словарь переводов, согласие на cookie).
- Исправление: подзапрос получает nonce основного запроса. Тест падает без исправления и проходит с ним.

### TASK-06 — отсутствие AJAX-обработки капчи, найденное при проверке
- Закрыт в 3.34.0 (коммит `d727cf2`): капча обновляется после каждой отправки.

### TASK-07 — нагрузка и обновление на больших данных

- Ответственный: Release Auditor.
