# Онлайн-оплата — тестова конфігурація

## Базові способи

Платформа містить банківський переказ і оплату при отриманні. Для UAH у 2.5.0 додано hosted mono acquiring: номер картки, Apple Pay/Google Pay та інші платіжні дані обробляються на стороні платіжного провайдера, а не в Nexora Commerce.

## Увімкнення mono acquiring

У `.env.local` додайте:

MONOBANK_ACQUIRING_ENABLED=1
MONOBANK_ACQUIRING_API_BASE=https://api.monobank.ua
MONOBANK_ACQUIRING_TOKEN=ВАШ_ТЕСТОВИЙ_АБО_PRODUCTION_TOKEN

`APP_PUBLIC_URL` повинен містити реальний HTTPS URL магазину. Провайдер створює invoice з callback на `/webhooks/payments/monobank` та поверненням покупця на `/payment/return/{order}`.

Для тестового магазину використовуйте тестовий токен провайдера. Не зберігайте токени в Git або в публічному каталозі.

## Webhook

Webhook приймається тільки після ECDSA-перевірки `X-Sign`. Відкритий ключ провайдера кешується та оновлюється, якщо перевірка поточним ключем перестала проходити.

Browser redirect не вважається підтвердженням оплати. Остаточний paid/failed/refunded статус надходить від провайдера.

## Резерв товару

Для онлайн-оплати фізичний товар резервується на час оплати. Успішний платіж переводить резерв у фактичне списання зі складу. Failure/expiry/cancel звільняють активний резерв. Для mono базовий invoice має короткий резерв з невеликим запасом понад термін оплати.

Додайте cron/планувальник для регулярного запуску:

php bin/console commerce:orders:expire-unpaid --limit=100

## Адміністрування

Замовлення: `/admin/orders`.

Банківський переказ можна підтвердити вручну. Неоплачене замовлення можна скасувати; для активного online invoice система спочатку намагається інвалідувати invoice у провайдера і лише потім звільняє резерв. Для підтвердженої mono-оплати доступний запит на повне повернення; фінальний статус повернення підтверджує провайдер.
