## §1 Конструктор (Builder)

### 1.1 Какие конструкторы есть (важно)
- Конструктор макета один, 5 типов: `home | product | checkout | category | cart`. Тип проверяет `LayoutRevisionStore::assertType` и `requirements` маршрутов (`home|product|checkout|category|cart`).
- Шапка и подвал НЕ в конструкторе. `LayoutSchemaValidator::allowedForType` знает `header`/`footer`, но `assertType` их не пропускает, маршрута нет. Шапка и подвал = меню (`Appearance → Navigation`, `StorefrontLayoutExtension::menu('header'|'footer'|'utility')`, шаблон `admin/appearance/navigation.html.twig`).
- Лендинг: свой редактор `themes/default/templates/admin/appearance/landing.html.twig`, не builder.js. Контакты/чат: `contact_widget`, `support_chat`. Это не layout schema.
- Все 5 типов используют один `builder.js`, один шаблон `builder.html.twig`, одну схему `{schema_version:1, blocks:[...]}`.
- `/admin/appearance/editor` (`admin_visual_store_editor`, `VisualStoreEditorAdminController`, шаблон `editor.html.twig`) — обзорная страница: слева список страниц, в центре iframe `[data-preview-frame]` с переключателем устройств (`data-preview-size`) и кнопкой обновления (`frame.src=frame.src`), справа ссылка «Редагувати блоки» на конструктор. Свойств блока не редактирует.

### 1.5 `src/Modules/Appearance/Builder/*`
- `LayoutRevisionStore` (readonly; Connection, LayoutSchemaValidator, SafeLayoutProvider, ?LayoutPreviewToken, ?RequestStack):
  - `active($storeId,$type): array` — если в главном запросе есть `?_layout_preview=<валидный токен>` и есть draft → возвращает draft; иначе последний `published`; иначе `SafeLayoutProvider`.
  - `publishedOrNull`, `draft`, `saveDraft($storeId,$type,$layout,?$adminId): int` (в транзакции DELETE всех draft этого store+type и INSERT новой строки: у магазина всегда ≤1 черновика на тип), `publish(...)` (старый published → `archived`, INSERT published), `history($storeId,$type,$limit=20..50)` (id,status,created_by,created_at,published_at), `rollback`.
  - Все читающие методы проходят через `LayoutSchemaValidator::validate`.
- `LayoutPreviewToken` (`valid(token,storeId,type)`, `issue(storeId,type)`): токен `"<exp>.<hmac32>"`, TTL 1800 с, HMAC-SHA256 от `layout-preview|store|type|exp` с `%kernel.secret%`. Привязка к store+type, не к админу.
- `LayoutPreviewResponseSubscriber`: на `KernelEvents::RESPONSE` (приоритет -100), для главного запроса с `_layout_preview` ставит `Cache-Control: no-store, private` и `X-Robots-Tag: noindex, nofollow`.
- `LayoutSchemaValidator::validate($layout, ?$layoutType)`: `schema_version===1`, ≤200 блоков, id `^[a-z][a-z0-9_-]{0,63}$` и уникален, component из `ALLOWED_COMPONENTS` (+ допустимый для типа через `allowedForType`) ИЛИ блок модуля (`ExtensionContributionRegistry::hasBuilderComponent`) ИЛИ отсутствующий модуль (`extension.<code>.<id>` → сохраняется с `missing_extension:true`). props ≤64, style ≤32, visibility ≤16 ключей; значения: строки `strip_tags` ≤4000, скаляры, вложенные массивы глубиной ≤4 и ≤50 элементов. Новое поле/компонент требует правки `ALLOWED_COMPONENTS` и `allowedForType`.
- `SafeLayoutProvider`: методы `storefront()` (home), `cart()`, `category()`, `checkout()`, `product()` — дефолтные макеты, когда нет published.
- `LayoutSnippetStore`: `all($storeId,$type)` (типы `$type` и `any`), `save(...)` (upsert по `(store_id,name)`), `delete($storeId,$id)`.

### 1.6 Как draft доходит до iframe (важное для «живого предпросмотра»)
- iframe грузит реальную страницу магазина с токеном. Токен читает ТОЛЬКО `LayoutRevisionStore::active()`.
- Кто какой метод вызывает (это ломает предпросмотр для большинства типов):
  - home: `HomeController` (`:77,:97,:145`) → `active()` → ЧЕРНОВИК ПОКАЗЫВАЕТСЯ.
  - checkout: `CheckoutLayoutService.php:23` — `publishedOrNull() ?? active()`; черновик виден только если нет опубликованной версии.
  - category: `CategoryLayoutService.php:25` → `publishedOrNull()` — черновик НЕ виден.
  - cart: `CartLayoutService.php:25` → `publishedOrNull()` — НЕ виден.
  - product: `ProductPageLayoutLoader.php:53` → `publishedOrNull()` — НЕ виден.
- Предпросмотр показывает уже СОХРАНЁННЫЙ черновик: несохранённое состояние браузера (`data` в JS) на сервер не уходит. Для живого обновления нужен либо автосохранение черновика (ajax `saveDraft`) + перезагрузка iframe, либо `postMessage`/передача layout в запрос предпросмотра (сервер читает layout из подписанного токена/кеша).
- CSP: `SecurityHeadersSubscriber.php:56` `frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN` (`:74`) — iframe той же origin работает.
- Page cache в приложении нет (grep `PageCache` пусто); `no-store` ставится подписчиком.

### 1.10 Риски для работы над конструктором (коротко)
1. Живой предпросмотр: draft виден в iframe только у home (и у checkout без published). Для category/cart/product loaders вызывают `publishedOrNull()`; чинить в 3 сервисах + `ProductPageLayoutLoader`, иначе iframe врёт.
2. Инспектор не имеет серверной схемы: поля блока модуля = общие title/text/image. Схема `blocks/*.schema.json` существует только в манифесте/валидаторе пакета; её надо отдавать в страницу (`extension_components` + разобранная схема) и рисовать в `renderInspector`. Рендер на витрине для product читает только title/text, для home/category/cart рендерера блоков модулей нет.
3. Конкурентность: нет ни версии, ни блокировки; черновик перетирается DELETE+INSERT, а сохранение — полная перезагрузка страницы (form POST). Автосохранение/ajax потребует нового JSON-эндпоинта + CSRF `layout_builder_<type>` + `base_revision_id`.
4. builder.js — 41 «сверхдлинная» строка, без модулей; Undo/Redo, правка схемы, drag&drop придётся делать в этом же файле или выносить в TS (`assets/admin/features/*.ts` уже есть, vite собирает `adminBuilder`).
